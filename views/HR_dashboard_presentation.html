Development of a Web-Based Recruitment and Applicant Management System (R-AMS)

A centralized digital hub designed to replace manual data handling with a secure, automated workflow for XBP Global Company.

The Problem: Manual Workflows

  • Recruitment often relies on manual, spreadsheet-based methods.
  • Data is scattered across multiple Excel and Google Sheets files managed by different staff members, leading to inconsistent data entry.
  • Paper application forms require tedious manual re-encoding.
  • This fragmented process leads to duplicate records and significant delays in scheduling interviews.
  • HR managers struggle to track real-time performance or generate the reports needed to make efficient hiring decisions.
Figure 1. Current manual system

The Solution: Three-Tier Architecture

R-AMS is designed to solve these bottlenecks by providing a robust Three-Tier system:

Tier 1

Applicant Web Form

Candidates submit data digitally, and an automated pre-screening algorithm calculates qualification scores.

Tier 2

HR Dashboard

A centralized command center to manage records, perform bulk CSV uploads, and track real-time analytics.

Tier 3

Interviewer Portal

A restricted space for department heads to review assigned candidates and submit standardized feedback.

System Logic & FAQ

Deep dive into the mathematical algorithms, constraints, and operational logic powering R-AMS.

How is the Pre-Screening Score Calculated?

The system evaluates applicants instantly upon form submission based on four key metrics: Education, Experience, Skills, and Hard Gates. The core formula is:

Total Score = Education + Experience + Skills
  • Contextual Scoring: Points adapt based on the role. Entry-level roles award higher points for lower education levels compared to Professional roles.
  • Experience: Weighted heavily as the primary predictor of readiness (e.g., 5+ Years = 50 pts, 0 Years = 5 pts).
  • Intelligent Skill Mapping: Awards +5 Premium points for exact category matches and +1 for general skills.
Hard Gate (Auto-Fail) Logic:

If an applicant fails a strict requirement (e.g., applying for IT without an IT/CS degree, or Manager without experience), their score is forcefully reset to 0 and flagged as "Underqualified" regardless of other points.

How are Recruiters Scored / Evaluated?

Recruiter performance metrics are tracked dynamically based on pipeline movement. They are evaluated on:

  • Total Handled vs. Deployed: Tracks conversion volume.
  • Acceptance & Withdrawal Rates: Measures candidate retention.
  • Average Time to Hire: Calculates the velocity of the recruiter's pipeline using the formula:
Avg Time to Hire = Total Sum of (Joining Date - Application Date) / Total Hired Applicants

How does the Requisition feature work?

The Requisition Modal is a centralized tool for tracking approved headcount requests across various company projects. Its metrics update dynamically based on actions taken in the main HR table:

  • Data Mapping: When HR edits an applicant's profile, they assign them a specific Requisition ID. This links the applicant's progress directly to the job order.
  • Offered: The system automatically counts all applicants tied to the Requisition ID whose "Offer" field has been updated to Accepted.
  • Joined: The system counts applicants tied to the Requisition ID whose main recruitment status has successfully reached Deployed.

The system then calculates the remaining open slots (Balance) using this automated formula:

Balance=Approved Headcount-Joined+Offered
  • It also tracks Aging to show exactly how many days a job order has remained open since its approval date, helping prioritize urgent hiring needs.

Bulk Upload: Guide & Limitations

The Bulk Upload module utilizes PapaParse.js to rapidly inject multiple records via CSV while validating formatting.

  • Pre-screening Sync: Imported records automatically undergo the same scoring algorithm as manual web forms to maintain data integrity.
  • Validation: The system detects missing fields and flags duplicate email addresses to prevent corrupted data.
  • Limitation: Because processing occurs client-side within the browser, uploading excessively massive datasets (e.g., 10,000+ rows) simultaneously may cause temporary browser lag. Chunking files is recommended for massive imports.

How do Custom Analytics function?

Instead of static reports, the Custom Analytics suite allows HR to generate real-time visual data based on specific queries.

  • Users can define the Group By (e.g., Status, Source, Recruiter) and the Metric (e.g., Count, Average Score, Average Age).
  • Data can be toggled instantly between Bar Charts, Doughnut Charts, or Data Datasheets using Chart.js.
  • The engine respects active Smart Filters and can isolate data by specific date ranges or locations.

How do Interview Notifications trigger?

The notification bell serves as a proactive reminder for scheduled assessments. The logic requires two conditions to trigger:

  • The applicant must have an assigned Interview Date/Time.
  • Their status must currently be set to Initial Interview or Final Interview.
Role-Based Access (RBAC): For Department Managers on the Interviewer Dashboard, the logic strictly filters the notification feed to display only the specific applicants mapped to their unique Employee ID.
